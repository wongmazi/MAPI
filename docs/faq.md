# 常见问题（FAQ）

## 我还能在库里面做什么？

可以从“想法→原型→脚本/插件”的路径逐步扩展：

1. **记录需求与想法**
   - 先把要自动化的流程写成“输入 → 处理 → 输出”的小卡片。
   - 这能帮助后续选择合适的工具（CAD 脚本、Office 宏、Midas Civil 命令流等）。

2. **沉淀可复用的模板或脚本**
   - 例如：CAD 图层整理脚本、Excel 报表模板、Midas Civil 参数化命令流。
   - 先做“最小可运行原型”，再逐步完善。

3. **补全文档与流程**
   - 为新人写“如何跑起来”的说明与示例。
   - 记录限制条件、输入输出格式、常见错误与排查方法。

4. **建立协作与规范**
   - 通过 Issue 或文档记录需求、TODO、待验证的想法。
   - 使用 Pull Request 讨论和沉淀改动原因。

## 版本数量代表什么？

在 Git 与 GitHub 的语境里，**“版本数量”通常有几种可能的含义**，需要看你在页面中看到的具体位置：

1. **提交（Commit）数量**
   - 每次 `git commit` 就会产生一个新的提交记录。
   - 所以“提交数量”≈“仓库的变更次数”。

2. **Release（发布版本）数量**
   - Release 是基于 Git tag 的“对外发布版本”。
   - 通常用于标记稳定版或里程碑版本。

3. **Tag（标签）数量**
   - Tag 用于标记某个特定提交，例如 `v1.0.0`。
   - 并不一定代表正式发布，更多是标记点。

**简单理解：**
- 提交数量 = 你改动并记录了多少次。
- Release/Tag 数量 = 你对外声明了多少个“版本节点”。
